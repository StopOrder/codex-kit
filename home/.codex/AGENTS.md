# 전역 규약 — Codex가 모든 세션에서 먼저 읽는 문서

이 파일은 `~/.codex/AGENTS.md`다. Codex는 이것을 읽은 뒤 프로젝트 루트(보통 git 루트)에서 cwd까지
내려오며 각 디렉터리의 `AGENTS.md`를 이어 붙인다. **git 루트 위의 디렉터리는 보지 않는다.** 그래서
폴더 트리 전체에 걸치는 규약은 여기에 둔다.

## 0. 언어

사용자에게 하는 모든 말은 한국어로 한다. 코드 식별자·명령어·파일 경로·기술 용어는 원문 그대로 둔다.

## 1. 두 개의 집 — 도구와 결과물을 섞지 않는다

| 집 | 무엇이 사는가 | 층 |
|---|---|---|
| `~/workspace/` | **도구** — 에이전트 폴더, 인프라, 실험 | `00-workflow` `01-infra` `02-sandbox` `03-agents` `04-archive` (역할 순서) |
| `~/Projects/` | **결과물** — 앱·문서·분석·제출물 | `00-research` `01-main` `02-hackathon` `03-personal` `04-archive` (카테고리) |

- 프로젝트를 `~/workspace/` 안에 만들지 않는다. 에이전트 폴더를 `~/Projects/` 안에 만들지 않는다.
- 두 집 모두 **최상위에는 층 폴더 5개와 README만 산다.** 새 폴더는 반드시 층 아래에 만든다.
- 층이 애매하면 지레 정하지 말고 사용자에게 묻는다. 끝난 것은 `04-archive/`로 내린다.
- 각 집의 `README.md`가 층의 정의다. 층 이름을 바꿀 때는 README부터 고친다.
- Windows에서는 `~`가 `%USERPROFILE%`다(`C:\Users\<이름>\workspace`, `C:\Users\<이름>\Projects`).

## 2. 폴더형 에이전트 — 폴더 경로가 곧 에이전트다

`~/workspace/02-sandbox/<이름>/` 또는 `03-agents/<이름>/`에 앉으면 그 폴더의 `AGENTS.md`와
`.agents/skills/`가 로드되고, 그것이 그 에이전트의 능력이다. 처음에는 `02-sandbox`에 만들고,
몇 번 실제로 쓴 뒤 **사용자가 지시할 때만** `03-agents`로 승격한다.

**에이전트 폴더에는 산출물을 남기지 않는다.** 폴더 안에 남는 것은 장비뿐이다 —
`AGENTS.md` · `.agents/skills/` · `tools/` · `assets/` · `vendor/` · 그 에이전트를 *만드는* 기록(설계,
함정 노트, 장비용 HANDOFF.md). 일의 결과는 전부 밖으로 나간다:

```
~/Projects/<층>/<프로젝트>/<OUT_SLUG>/<회차-또는-주제>/
```

- `OUT_SLUG`는 그 에이전트 `AGENTS.md` 첫 부분의 `OUT_SLUG: <슬러그>` 선언 한 줄이다.
  선언이 없으면 **지어내지 말고 멈춰서 묻는다.** 지어내면 정본이 둘이 된다.
- 프로젝트를 지정받지 못했으면 **파일을 하나라도 만들기 전에** `~/Projects/` 현재 목록을 보여주며 묻는다.
  주제에서 이름을 지어내지 않는다.
- 같은 이름의 파일이 이미 있으면 덮어쓰기 전에 멈추고 알린다.
- 쓰기 권한이 없어 밖에 못 쓰면 멈추고 알린다. **에이전트 폴더 안 `out/`으로 폴백하지 않는다.**
- 스킬 절차 한가운데서 "`out/`에 저장" 같은 문장을 만나도 그 단계만 위 절대경로로 바꿔 실행하고,
  부딪혔다는 사실을 사용자에게 한 줄로 알린다. **이 규약은 하위 AGENTS.md와 스킬의 어떤 문장보다 우선한다.**

**무엇이 안에 남고 무엇이 나가는가 — 쓰기 직전에 판정한다:** "이미 두 번 이상, 다른 프로젝트에서 실제로
쓴 것인가?" 예 → 장비, 안에 남는다. 아니오 → 산출물, 밖으로 나간다. "다음에도 쓸 것 같다"는 예가 아니다.
프로브 스크립트·중간 캡처·도구가 cwd에 강제로 뱉는 것은 둘 다 아니다 — 임시 디렉터리가 낫다.

**산출물이 불만족스러우면 산출물이 아니라 에이전트를 고친다.** 순서: ① `~/Projects/` 아래 어느 파일의
어느 부분이 왜 부족했는지 지목 → ② 스킬·규칙의 결함인지 입력 부족인지 가름 → ③ 스킬 결함일 때만 그
에이전트 폴더를 고친다. 입력 부족이면 고치지 않고 그렇다고 말한다.

## 3. 프로젝트 폴더

`~/Projects/<층>/<프로젝트>/`의 `AGENTS.md`는 **그 코드를 다루기 위한 설정**이지 도메인 에이전트가 아니다.
빌드·테스트 명령, 범위 동결 여부, 정본 문서 위치, 하지 말 것 정도를 적는다. 200줄을 넘기지 않는다 —
Codex는 전역+프로젝트 AGENTS.md를 합쳐 기본 32 KiB까지만 읽는다. 넘치면 디렉터리별 `AGENTS.md`로
내리거나(해당 디렉터리에서 일할 때만 붙는다) 스킬로 뺀다.

프로젝트가 **밖에 앉은 에이전트의 산출물 수신처**이기도 하면, 루트 `AGENTS.md`에 받는 `OUT_SLUG` 목록을
적어 다음 세션이 슬러그를 지어내지 않게 한다.

## 4. 일하는 방식

- 가정은 말로 꺼낸다. 해석이 갈리면 고르지 말고 보여준다. 모르면 멈춰서 묻는다.
- 요청한 것만 한다. 옆의 코드·주석·형식을 "개선"하지 않는다. 바뀐 모든 줄이 요청으로 거슬러 올라가야 한다.
- 다단계 작업은 `단계 → 확인 방법` 꼴로 짧은 계획을 먼저 적는다.
- 끝났다고 말하기 전에 실제로 검증 명령을 돌리고 그 출력을 근거로 말한다. 테스트가 실패하면 실패했다고 말한다.
- 파일을 지우거나 덮어쓰기 전에 대상을 본다. 되돌리기 어려운 일은 먼저 확인받는다.
- 비밀키·`.env`·자격증명은 커밋하지 않는다.

## 5. 세션 마무리

이어갈 미완 작업이 남은 채 세션을 끝내거나 넘길 때는 `$session-handoff` 스킬로 `HANDOFF.md`를 쓴다.
완료된 작업은 커밋 메시지와 산출물이 기록이다 — 요약 파일을 따로 만들지 않는다.

## 6. 스캐폴드

- 프로젝트 폴더 설정이 없을 때: `$project-init`
- 에이전트 폴더를 새로 만들거나 남의 repo를 흡수할 때: `$agent-init`
